# Артём Ребриков — портфолио

Портфолио разработчика: сайты для бизнеса, продуктовые инструменты, backend и AI.
React 18 + TypeScript + Vite. Публикация — существующий GitHub Pages workflow.

## Возможности

- Девять отобранных кейсов с задачей, реализацией, результатом и стеком.
- Masterstroy — основной кейс. ERP-проект исключён из публикации.
- У закрытых проектов нет ссылок на приватные репозитории.
- Кейсы открываются в доступном нативном `dialog`: Escape, возврат фокуса,
  блокировка фоновой прокрутки и прямые ссылки вида `#project/masterstroy`.
- Фильтры проектов, интерактивные схемы, CSS 3D, наклон карточек.
- Анимация отключается кнопкой и системным `prefers-reduced-motion`.
- Telegram и почта с предварительно выбранной темой обращения.

## Демонстрации

### Masterstroy

Сайт [masterstroy44.ru](https://masterstroy44.ru/) возвращает
`X-Frame-Options: SAMEORIGIN` (проверено 09.09.2026), поэтому прямой iframe
с GitHub Pages блокируется браузером. Настройки рабочего сайта не изменялись.

В `public/demos/masterstroy` — демонстрационная копия семи публичных страниц.
Экспорт получает только публичный HTML, CSS, JS и шрифты по HTTPS.
Приватный PHP-код, конфигурация сервера и ключи в портфолио не копируются.
Фото остаются на публичном сервере Masterstroy, поэтому для них нужно подключение
к интернету. Формы, аналитика и встроенные сторонние фреймы удалены.
CSP запрещает сетевые API-запросы, формы и сторонние фреймы; iframe дополнительно
ограничен sandbox. Серверные фильтры, карты и отправка заявок не являются
функциями копии. Интерфейс явно сообщает о демонстрационном режиме и дате.
Кнопки над просмотром открывают экспортированные страницы.

Обновить публичную копию:

```bash
npm run demo:refresh
```

Экспорт не входит в сборку: внешняя недоступность не ломает повторную публикацию.
После обновления повторите сборку и проверку.

### Wordle

Живая игра загружается с существующего GitHub Pages внутри портфолио,
с переключением ширины и кнопкой перезагрузки. Внешние сайты могут менять
доступность и правила встраивания.

### Upscaler

Ползунок сравнивает настоящие `before.jpg` / `after.jpg` из материалов проекта,
есть изображение интерфейса приложения. Это просмотр результата, а не запуск
нейросети в браузере.

Остальные кейсы показывают описания и интерактивные схемы работы.
Они не выдают иллюстрации за подключённые приложения и не обращаются к
приватным backend-сервисам.

## Разработка и проверка

```bash
npm ci
npm run dev
VITE_BASE=/Portfolio/ npm run build
npm run verify
```

`verify` проверяет список разрешённых публичных репозиториев, отсутствие
исключённого проекта, локальные ресурсы, ограничения демо и пути production-сборки.
Это структурная проверка, не браузерное тестирование.

GitHub Actions публикует `dist` при push в `main`; base вычисляется из имени
репозитория, как и в предыдущей версии.

## Где менять контент

- `src/data/caseStudies.ts` — актуальные данные и ссылки на проекты.
- `src/components/Showcase.tsx` — карточки, кейсы, демонстрации.
- `src/App.tsx` — первый экран, услуги, контакты.
- `src/index.css`, `src/showcase.css` — визуальная система и адаптивы.
- `public/projects` — публичные изображения из исходных проектов.

Ссылку `source` добавляйте только после проверки публичности репозитория.
Для закрытого проекта поле нужно оставлять отсутствующим.
Не публикуйте ключи, дампы, пользовательские данные или приватные конфигурации.

## Принципы

Сначала задача и результат, затем технические подробности; без вымышленных метрик
и обещаний коммерческого эффекта. Короткие пути к работам и контакту, крупный
основной текст, нативная прокрутка, ленивое подключение демо, возможность уменьшить
движение.

Технические справочники:
[встраивание и frame-ancestors (MDN)](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors),
[уменьшение анимации (web.dev)](https://web.dev/articles/prefers-reduced-motion).
